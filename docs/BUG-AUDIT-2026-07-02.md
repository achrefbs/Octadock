# Octadock Deep Audit — 2026-07-02

This audit re-verified every finding in [`BUG-AUDIT.md`](BUG-AUDIT.md) (the 2026-07-01
consolidation) against the **current** code, hunted for new defects, and fixed a
prioritized set. Five independent review agents (Fable 5) each swept one area of the
codebase; every claim below was traced to a concrete file/line and mechanism, not taken
on trust.

and the current docs pass are summarized in `PROJECT-STATE.md` and `ROADMAP.md`.

## Part 2 — New findings (this audit)

Severity + confidence as assessed by the reviewing agents and cross-checked. IDs are
grouped by area: **A** = capture UX, **B** = app shell, **C** = platform/CLI, **D** =
core/data.

### Fixed this session

| ID | Sev | Title | Fix |
|---|---|---|---|
| C-1 | **High** | Named-pipe IPC had no ACL/`CurrentUserOnly` → local cross-user / low-integrity command injection on a deterministically-named pipe | `PipeOptions.CurrentUserOnly` on server + both clients |
| C-6 | Med | IPC connections had no read timeout → a connect-without-send pins a server instance (resource exhaustion) | 5s linked-CTS read timeout per connection |
| B-1 | **High** | `IRetentionService` was **never invoked** — History "retention" was inert; soft-deleted captures and their files were never purged (unbounded disk growth) | Wired into startup + a 6-hour `DispatcherTimer`, stopped on exit |
| M14 | Med | Retention deleted files *before* the DB hard-delete; a DB failure orphaned files / left rows pointing at missing files | Reordered: hard-delete row first, then files |
| A-1 / H4 | **High** | Dragging a selection past a monitor edge produced an over-size rect; moving it then threw `ArgumentException` on every mouse-move (error-toast loop) | Clamp rubber-band on draw; guard the move clamp bounds |
| M1 | Med | Selection edge handles (top-center, etc.) resized both axes instead of the dragged edge | Edge-aware `ResizeFromHandle` |
| A-9 | Low | Selection drag state not reset if mouse capture was stolen (Win key / focus-stealing popup) | Added `LostMouseCapture` reset |
| B-2 | **High** | Locked click-through pins could be impossible to unlock on scaled monitors (unlock hit-test compared physical cursor to DIP bounds) | Compare against `CurrentPhysicalBounds()` |
| B-8 | Low | Pin "Save image" wrote PNG bytes into a `.jpg` file | Encoder chosen by chosen extension |
| B-4 | Med | Hotkey recorder accepted bare, modifier-less keys → registers a global hotkey that hijacks normal typing | Require a modifier unless the key is F1–F24 / PrintScreen / Pause / media |
| B-10 | Low | PrintScreen (delivered only on key-up) could never be recorded as a hotkey | Handle `OnPreviewKeyUp` for `Key.Snapshot` |
| D-1 | Med | Hotkeys on unmapped VKs (OEM punctuation, numpad) silently reverted to defaults after restart (`ToString`↔`TryParse` asymmetry) | Parse `0x..` hex key tokens |
| A-3 | Med | WPF URI bitmap cache served **stale pixels** after a shelf flip/rotate rewrote the file in place | `BitmapCreateOptions.IgnoreImageCache` |
| D-2 | Med | `.octadock` save truncated the destination with `FileMode.Create`; cancellation/disk-full mid-flush corrupted an existing project | Write to temp file + atomic `File.Move(overwrite)` |
| D-3 | Low | A manifest with explicit `"canvas": null` / `"metadata": null` threw `NullReferenceException` on load | Null-coalesce the sections |
| D-4 | Low | `GetEnum` accepted arbitrary numbers (`action=999`) → undefined enum bypassing documented defaults | `Enum.IsDefined` guard |
| D-5 | Low | Command parser accepted zero/negative region width/height | Reject non-positive extents (origin may still be negative) |
| D-6 | Low | Reserved-name guard ran before truncation, so a truncated name could re-expose `CON`/`PRN`/… | Re-check reserved names after truncation |
| D-8 | Low | `AnnotationDocument` used an unstable sort → objects sharing a z-index could reorder nondeterministically | Stable `OrderBy` |
| D-10 | Low | An unknown boolean flag greedily swallowed the following positional (`--silent C:\img.png` lost the path silently) | Only whitelisted options consume a value |
| C-4 | Low | `Kernel32.GetLastError()` used instead of `Marshal.GetLastPInvokeError()` after `SetLastError` P/Invokes (unreliable error codes) | Switched both call sites |

**New regression tests added (14):** unmapped-VK hotkey round-trip and out-of-range
rejection; unknown-flag-doesn't-swallow-positional; non-positive vs negative region
extents; numeric-enum rejection; atomic-save survives overwrite and cancellation;

## Part 3 — Frontend improvements (shipped)

Implemented and compile-verified:

- **Accent buttons no longer vanish on hover.** The tool/icon button templates were
  restructured with a stacked *StateLayer* overlay, so hover/pressed tint the accent
  fill instead of replacing it. This also fixed the editor's active-tool highlight.
- **Keyboard focus rings** on all themed buttons (new `Octadock.Brush.FocusRing`).
- **Light theme accent** darkened `#0D9488` → `#0F766E` so white button text clears
  WCAG AA (~5.5:1); light hover/pressed feedback bumped to be visible on white.
- **New semantic tokens** in both palettes: `FocusRing`, `OnDanger`, `InputBackground`,
  `SelectionSubtle`.
- **Shelf card entrance animation** (fade + slide-up) and a **no-jiggle active ring**
  (constant 2px border, brush-only swap) so the stack no longer shifts on selection.
- **Dialog keyboard**: `IsDefault`/`IsCancel` on the About and First-run dialogs.

### Recommended larger frontend follow-ups (from the review)

1. **Dark title bars** via `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE)` —
   the single highest-impact visual change (dark windows currently get white title bars).
2. **Control theme pack** — TextBox, CheckBox, ComboBox, TabItem, Slider, ScrollBar,
   ContextMenu, ToolTip are all still Win32-default and clash with the dark theme.
3. Unify icons on Segoe MDL2 (a pin button currently renders a color emoji 💾).
4. Fix the editor selection accent (`RgbaColor.Accent` is blue `#2F6FED` while the app
   is teal).

## Part 4 — Repo hygiene note

The working tree carries **pre-existing CRLF/LF line-ending churn**: ~49 files differ
from `HEAD` only in line endings (no content change), which inflates `git diff`. This
predates the fixes here. Recommend, in an interactive session: add a `.gitattributes`
(`* text=auto eol=crlf`), run `git add --renormalize .`, and commit separately so the
functional diff stays reviewable. The genuine content changes from this session are ~12
files (listed in Parts 2–3).
