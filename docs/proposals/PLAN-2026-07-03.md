# Octadock — fix and feature plan (agreed 2026-07-02)

Status update 2026-07-03: this plan is now a historical proposal. The active
implementation plan is `../ROADMAP.md`; the current as-built state is
`../PROJECT-STATE.md`. Several items below are now implemented or partially
implemented on `codex/fix-tray-stt-follow`.

Ordered by priority. "Session" = one working session with build + on-device
verification. Bugs first, then the visible-feedback work, then the toolkit.

## P0 — remaining capture bugs (1 session)

**1. Overlay undersized on the 100%-scale monitor (PHL).**
Root cause: overlays are created on the primary (175%) monitor and then moved,
so WPF sizes them with the wrong DPI (`1097x617` DIPs logged for a 1920x1080
target). Fix: give each `SelectionOverlayWindow` a pre-show `Left/Top` hint
inside its target monitor so the HWND is created there at the right DPI from
birth; keep `PositionPhysical` + the new `OnDpiChanged` re-assert as a safety
net; after `Loaded`, verify `GetWindowRect == monitor.Bounds` and log a warning
when it is not. Same treatment for the window-picker overlay (audit H3 — it was
fed the same virtualized coordinates before the DPI fix).

**2. Scrolling capture is invisible → make the session visible and controllable.**

Status: partially implemented. A `ScrollingSessionPill` now provides visible
manual vertical scrolling status. Auto-scroll/horizontal support remain planned.
Keep the engine; replace the silent 20s loop with a session UI:
- A small status pill (same glass style as the recording pill below) pinned near
  the selected region: "Scroll now · 1,240 px stitched · Enter to finish · Esc
  to cancel".
- No fixed deadline while stitching is progressing; idle-finish stays (~2s) but
  Enter/click finishes immediately, Esc cancels.
- When frames stop matching (animated content, too-fast scroll), say so in the
  pill instead of silently truncating.

## P1 — recording and overlay chrome (1–2 sessions)

**3. Recording indicator pill.** Small, glassy (DWM acrylic backdrop), minimal:
red dot + mm:ss timer + stop, pause on hover, draggable, capture-excluded so it
never appears in the video, tray item mirrors state ("Stop Recording"). Powered
by the engine's existing `ProgressChanged` event — no engine changes needed.

Status: implemented as a first slice. It still needs selected-area recording and
real audio encoding to satisfy the recording MVP.

**4. The permanent Octadock pill (the "small clean glassy overlay").**

Status: implemented as a bottom-center permanent Dock capsule with draggable
positioning and common actions. Shelf thumbnails do not yet dock into the capsule
as described here.
One persistent, compact glass dock that is Octadock's face on screen:
- Idle: a slim pill docked to a screen edge (drag to move, auto-dim).
- Capture: click = area capture; hold/right side = mode flyout (window,
  fullscreen, scrolling, OCR, record).
- Recording: the pill becomes the recording indicator (dot + timer + stop).
- New captures dock INTO the pill as thumbnails (the existing shelf cards become
  the pill's expanded state), so screenshots land in the same place the controls
  live.
- Settings: enable/disable, edge, opacity, auto-hide.
This replaces "tray-only + transient shelf" with the always-there control the
user asked for, while reusing ShelfService/pin plumbing.

## P2 — vibe-coding toolkit (per proposals, in order)

**5. File opener / Quick Look previews** — phase 1 as specced in
`file-preview-quicklook.md` + `examples/FilePreview/`: CSV + text/log providers,
zoom-from-icon animation (mockup approved), shelf-drop + `octadock open` +
protocol entry with confirmation, UNC blocked.

Status: partially implemented. The current syntax is
`octadock open --filepath <path>`. CSV/text/image/fallback previews and UNC
rejection exist; export, image add-to-shelf, and image pin actions are wired.
Source animation and Ask AI remain planned; shelf file-drop entry and
provider-aware preview badges are wired.

**6. Speech-to-text** — phase 1 as specced in the roadmap + `examples/Stt/`:
toggle mode (chord to start/stop), local Whisper (`base` model, downloaded on
first use), waveform HUD reusing the glass pill style, paste-at-cursor with
clipboard save/restore and elevated-window fallback, dictation dictionary for
code terms.

Status: partially implemented. Dock-triggered toggle dictation exists with local
Whisper/OpenAI provider selection, WASAPI capture, a dictation pill, code-term
hints, paste-at-cursor, configurable toggle hotkey, and local-only CLI toggle
entry. Hold-to-talk and live partials remain planned.

**7. Suggested next tools** (from the roadmap review, highest value for the
vibe-developer loop first):
- **OCR hotkey promotion** — nearly free now the gate fix is in; region → text
  on clipboard is a daily need. (S)
- **Clipboard history** — searchable ring of text+image clips, docked in the
  pill; must respect password-manager clipboard-exclusion formats. (M)
- **Code screenshot beautifier** — capture → framed, syntax-highlighted image
  for PRs/social; reuses the annotation/export pipeline. (M)
- **Command palette** — extend the all-in-one HUD into a fuzzy launcher for
  every Octadock action + recent captures/previews. (M)
- **"Ask AI about this"** — send a capture/preview/clipboard to a local or
  hosted model: explain this error, summarize this CSV, write a regex. Powers
  the CSV card's "Explain this file" too. (M, opt-in per privacy stance)
- Small utilities that fit the pill: color eyedropper (the loupe already
  samples pixels), text-transform toolbox (JSON pretty-print, Base64/JWT
  decode, hash), scratchpad notes as shelf items. (S each)

## P3 — the eight strategic bets (agreed 2026-07-02, sequenced after P2)

Beyond-the-plan bets from the founder, recorded so every P1/P2 decision stays
compatible with them:

1. **MCP server** — expose latest capture / OCR text / clipboard / prompt
   library as MCP tools for Cursor and Claude Code. Differentiator: curated,
   redaction-aware, fully local. (The command verb + service architecture maps
   1:1 onto MCP tools; the CLI's pipe transport can host it.)
2. **"Send to AI" targeting** — capture → annotate → type an instruction →
   routed to the chosen tool in one chord.
3. **Context Shelf** — bundle captures + OCR + snippets into one pasteable /
   MCP-exposed context blob. (Shelf items already carry the raw materials.)
4. **Grab Error** — OCR a terminal/dialog, detect the stack trace, emit a
   clean fenced code block.
5. **Auto-redact secrets** before anything reaches a cloud AI — solid fill or
   pixelate, never blur (both tools already exist in the editor).
6. **Local LLM "Ask AI"** via Ollama, offline by default.
7. **Voice prompting** — the local-Whisper STT positioned as the free, private
   Wispr Flow.
8. **Agent-run monitor** — TTS/toast when a build or Claude Code run finishes.

Status: not implemented and promoted. The active roadmap now names this
**Active AI Sessions / Agent Mission Control** and moves it earlier because it
is core to the vibe-developer direction.

Design constraints these impose today: keep every capture artifact reachable by
id through a service interface (MCP needs it), keep OCR output structured (Grab
Error needs spans), keep the redaction tools scriptable (auto-redact needs
them headless), and keep the glass pill componentized (it becomes the voice +
send-to-AI surface).
