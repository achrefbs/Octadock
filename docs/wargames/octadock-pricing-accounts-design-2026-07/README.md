# Octadock Pricing, Accounts, Gates, and Design System Wargame

This folder is the handoff packet for a second deep Fable pass.

The first pass stress-tested the core app plan: Capture Shelf, Context, file
preview, writeback, Explorer verbs, and package safety. This second pass should
stress-test how Octadock becomes a coherent product: pricing, accounts,
entitlements, feature gates, hosted usage, homepage messaging, and a locked
visual system for the app and website.

## How to Use

Point Fable at the repo root and paste the prompt in `FABLE_PROMPT.md`.

Recommended read order:

1. `FABLE_PROMPT.md`
2. `PROJECT_INPUTS.md`
3. `LIVE_PRICING_SOURCES.md`
4. `WARGAME_PLAN.md`
5. `OUTPUT_TEMPLATE.md`
6. Cross-referenced source docs listed in `PROJECT_INPUTS.md`

## Ground Rules

- Do not revive AI discovery or AI Sessions.
- Verify current public pricing from official sources before relying on any
  research number.
- Treat all account, subscription, hosted-AI, and payment decisions as product
  risk, not just implementation detail.
- Produce a concrete design system token proposal, not loose adjectives.
- Keep Octadock local-first: accounts and Pro must not block the core local app
  unless the final recommendation deliberately says so.
